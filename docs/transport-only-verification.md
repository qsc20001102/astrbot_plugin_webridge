## 真实 Linux 检查

在隔离的 Linux x86_64 环境内，以官方 AstrBot v4.29.4 镜像运行 `native/smoke.py`，容器禁止外网，使用全新临时目录。结果：

- 并发四次启动只创建一个引擎；PID、目录、版本、服务器 ID 和进程代次核验通过。
- 通过真实 `NativeView`、AstrBot 请求对象及 Native `/accounts` 创建账号，中文备注独立保存。
- 未登录时一键接入正确拒绝；通过真实 `PlatformManager` 检查微信消息适配器实例加载和卸载。
- 按实际身份请求停机，原进程退出码 0。
- 再启动后账号目录和中文备注保留，令牌和进程代次轮换，服务器 ID 不变。
- 仅操作隔离验证目录，没有登录微信、发送消息或修改生产容器和账号数据。

二维码修复追加了 `starting`、`resuming`、`authenticating` 等非终态、刷新恢复、冲突恢复、过期重试和取消的回归检查。在官方 Linux 镜像的 `--network none` 容器运行 `native/login_smoke.py`，真实返回 `starting`，原幂等键复用同一操作，且操作编号正确保留；没有连接微信服务。

另用真实框架管理器回归插件热加载：已保存机器人能重新创建，重复初始化不重复创建，卸载只停止微信消息适配器，网页聊天平台保留。

## 图片、消息与配置

保留原有纯接入规则、指令/参数交付、配置选取、群成员会话隔离、唤醒和白名单、@/引用、语音、视频、SSE 补发、持久化去重、撤回、幂等、部分成功与不确定回执检查。PDF 与原有业务处理代码不在运行包中。

新增 Native 测试验证 1280×2096 JPEG 原图与源文件字节/SHA-256 完全相同，PNG 生成完整尺寸 JPEG，长图与 50 MP JPEG 保留原尺寸；大图跨多个数据块重组并解密后与源图一致，预览数据只在首块发送，中途取消阻止后续上传。没有新增或猜测 protobuf 字段。

UI API 检查创建/登录幂等、响应丢失后复用键、二维码代次、账号身份、取消/退出、权限信息不外泄、平台失败回滚与静默跳过检测，以及单账号自动绑定不重复创建平台。内置引擎端口和令牌轮换不会重置平台状态库。

## 上一版视频画质回归记录

内置引擎取消了统一缩到长边 720、最高 2 Mbps 的旧策略。12 项视频准备测试通过，新增验证包含：1080×1920 H.264/AAC 与 60 帧 MP4 的源/播放字节及 SHA-256 相同；不兼容 MOV 转码到 1080×1920；4K 来源按完整高清范围处理；方形像素、旋转、帧率、完整时长、大小、取消与超时边界。Native Core/Media/Protocol/文档共 552 项通过，API/Simulator 共 66 项通过，1 项原有测试忽略；全工作区 Clippy 和格式检查通过。

保留已有 job 的已准备副本，避免更新后改变旧幂等任务的数据；新 job 的 `videoPreparation.sourcePreserved` 和哈希记录用于核对。该轮没有通过真实微信发送视频，收件端播放仍需验收。

## 本轮：收到视频忽略、发送取消额外限制

- Python 全量 482 项通过；接收视频不创建 AstrBot 事件、不下载，不自动回复。引用视频仅保留文字和引用信息。
- Native Core 332、Media 20、Protocol 203、API 51、Profile 145、Store 92、Simulator 15 项通过，共 858 项；1 项原有历史性能测试忽略。Rustfmt 和全工作区 Clippy 通过。
- 真实 FFmpeg 测试验证超过 50 MiB 的可解码 MP4 字节/SHA-256 保留、4K 与 120 帧来源保留、不兼容 4K 转码保持来源尺寸。原生大视频正常播放对象跨多个数据块核对完整性。
- Native 新接收视频与缩略图不自动下载；旧版本的待接收队列和已创建下载 job 不再续传。发送回读仍属于发送任务。
- 在无网络的官方 AstrBot v4.29.4 容器中，真实 Native API 上传并暂存 53,487,077 字节的 MP4，长度和 SHA-256 与源文件一致；未登录或提交微信发送。
- 完整运行包核对新引擎 SHA-256 和策略标记；源码补丁对固定提交的全新 LF 归档通过检查并可应用，生成的 TypeScript 契约与引擎输出一致。

取消 50 MiB 来源、约 25 MiB 播放、1080p、60 帧和 1 小时来源时长策略，不设按体积降低码率的预算。32 位描述符、SQLite 单值能力、内存、磁盘、准备超时、微信服务端和客户端能力仍有实际边界；不承诺任意大小都可发送，详见[视频说明](video-quality.md)。已有发送任务的准备副本继续复用，保持原幂等回执；新任务使用新策略。

## 验收边界

没有用真实微信账号完成手机确认，也没有向真实收件人发送图片、视频或语音。自动测试与容器检查证明代码路径、源图保留和本地集成，不能代替手机微信“查看原图”、实际播放及账号网络条件的验收。

PNG 等仍转换为 JPEG，预览仍压缩，已压缩的业务源图无法恢复。支持 QQ 私有接口的业务插件仍可能需要单独适配。集成版只支持 Linux x86_64 / glibc 2.36+。
