# 架构：内置引擎与纯消息接入层

微信消息适配器内置修改后的 Native v1.5.1，但回复策略仍由 AstrBot v4.29.4 处理。

```text
AstrBot 插件页面 → 微信账号 API → 插件管理的 Native 进程 → 微信登录
                                      ↑
微信 → Native /v1 → SSE / 游标 / 去重 → 标准 AstrBot 事件
                                          ↓
                          AstrBot 选择配置 → 会话隔离 → 消息管道
                                          ↓
微信 ← Native 图片/视频/语音与回执 ← 标准消息链 ← 模型或业务插件
```

| 模块 | 职责 |
| --- | --- |
| `main.py` | 注册平台、认证 UI API、会话构建器；启动引擎，卸载时先停止平台再停止引擎 |
| `runtime.py` | 检查 Linux/ELF/摘要，管理本插件进程、回环端口、短期令牌、目录锁、中文账号名称和身份核验 |
| `native_ui.py`、`views/accounts/` | 创建账号、扫码进度、二维码刷新/取消、退出登录、一键接入 |
| `config.py` | 平台通用字段与账号 ID，以及传输大小和超时限制 |
| `adapter.py` | 账号连接、live 消息身份与去重、接收队列、媒体下载、发送幂等和回执 |
| `event.py` | 标准组件转换、来源与会话 ID、回复发送 |
| `forward.py` | 微信聊天记录 XML 与 Node/Nodes 转换，复用官方解析设置与解析器 |
| `native_client.py` | 复用 Native `/v1`，核对身份、长度、SHA-256、格式及外部 URL |
| `state.py` | 微信消息适配器独立目录中的游标、去重、撤回、发送回执 |
| `bin/`、`native/` | Linux x86_64 引擎、清单、补丁、构建脚本与许可 |

## 进程与配置

插件启动前核对二进制与固定来源，再以独立目录、随机令牌和随机回环端口运行 `wx serve`。令牌经 stdin 传入，不出现在命令行和机器人配置中。就绪响应需匹配实际 PID、规范目录、版本、服务器 ID 和进程代次；停止只针对本插件持有的身份和进程。

平台状态使用账号 ID 与机器人 ID 建立稳定身份，端口或令牌轮换不会重置收发记录。二维码和登录结果只向已通过 AstrBot 登录认证的 UI 返回，原始引擎权限和凭据不向前端暴露。中文账号名称保存在微信消息适配器元数据中，不修改 Native 官方格式的账号/聊天数据库。

一键接入调用实际 `PlatformManager.reload`，写入的配置只有 `id`、`type`、`enable` 和 `account_id`；确认实例已创建才返回成功，失败恢复原配置。初次启动由框架初始化平台；插件热更新时重新加载仍指向旧代码的微信消息适配器实例。

旧配置中显式保存的外部 `server_url` 仍走原连接路径，便于停用前查看状态；新模板不展示外部参数，也不自动迁移旧账号。集成版请在新界面重新扫码、一键接入。

## 消息语义

EventBus 先按共享来源选择配置，再通过 `UNIQUE_SESSION_ID_BUILDERS` 应用成员隔离。本插件只注册 `webridge` 构建器，不修改框架默认配置。该注册表是 v4.29.4 的内部接口，升级框架时需要复查。

只消费 live incoming 消息；历史导入、自身回声、撤回按实际身份处理。适配器不判断正文是否值得回复，不添加模型提示词或自有白名单。媒体失败只记录传输错误；引用的媒体不可用时保留用户文字和引用信息。

收到视频时仅推进传输游标并记录去重状态，直接忽略；Native 的自动视频/缩略图下载也关闭。引用视频时仅保留文字和引用信息，不下载或交付 Video 组件。

输出图片继续使用 `kind: image`。插件上传源字节；内置引擎保留 JPEG 原字节，PNG 等转完整尺寸 JPEG。original 支持分块，standard/thumbnail 仍为小型预览。旧任务的准备模式保留，不改变旧回执对应的媒体。具体实现见 Native 补丁及合成图回归测试。

输出视频复用 Native job，兼容源保留字节，其他来源仅做编码兼容处理，不按大小、分辨率或帧率预算压缩。视频上传使用账号内的加密临时文件；确认服务端受理及账号媒体写入完成后延迟清理，来源元数据和幂等回执保留。已写入账号缓存的视频不重复写入 SQLite 媒体 BLOB，内容读取复用经过摘要核验的账号缓存。未完成、结果不确定及可重试任务保留来源。语音沿用现有准备流程，保留幂等、撤回检查和不确定结果。PDF 已移除，普通文件尚未实现。

合并转发转换为标准 Node/Nodes。接收时保留内嵌 XML 对应的节点结构；仅在框架已决定请求模型后，按该会话配置的 `provider_settings.quoted_message_parser` 限制递归，并复用官方解析器提供消息文本。引用记录交给官方 Reply 解析路径；不将记录内的命令和 @ 当作本条消息的唤醒信号。媒体保留类型占位符，暂不下载记录内的 CDN 附件。

发送时将相邻 Node 合成一张卡片，通过 Native 的 `kind: forward` 分支生成 subtype 19 聊天记录。该分支复用现有持久化 app-message 发送队列、幂等键、服务回执和状态查询；图片先暂存并沿用原图上传，再把 CDN 描述符写入记录。节点内语音、视频按原顺序拆为独立媒体，前后的文本、图片和嵌套节点组成相应卡片并保留署名与时间；其他不支持的组件在任何发送前拒绝。
