# 运维说明（集成版 1.1.2）

在“插件管理 → 微信消息适配器 → 可视化视图 → 微信管理”完成登录、查看状态和一键接入。无需单独配置 Native 地址或令牌。环境和 Docker 网络见[安装说明](setup.md)。

## 引擎未就绪

检查是否为完整 Linux x86_64 包，是否包含 `bin/linux-x86_64/wx` 与匹配清单，是否使用 glibc 2.36+。推荐已验证的官方 AstrBot v4.29.4 镜像。确认账号目录可写，只有一个进程使用它；然后点击“重新启动”。仓库和发行包均包含二进制；文件缺失时重新安装完整包，或按 `native/README.md` 重建引擎。

插件只操作自己创建的引擎进程，不发现、接管或终止旧 Native Docker 容器。切换集成版时应自行停用旧机器人与旧 Native，再扫码登录新账号，保留原数据。

## 登录和不回复

本版启动日志包含 `integrated-20261110-media-lifecycle`。安装更新后完整重启 AstrBot，再使用已有账号获取二维码，无须删除账号或数据。只刷新旧页面不能更新后端代码。

修复版会继续等待二维码，刷新或重新打开页面也能恢复已有登录进度。二维码过期后可重新获取；持续的登录冲突会显示具体提示，日志保留安全的错误码，不显示令牌或原始服务响应。

1. 扫码后在手机确认；确认卡住时检查手机与服务器局域网互通及回调端口 8050～8100。Linux Docker 推荐宿主机网络。
2. 登录成功后点击“一键接入 AstrBot”。检查新机器人已启用，并选择正确配置文件。
3. 检查配置中的唤醒词、私聊前缀、白名单、插件范围、模型和 ASR/TTS。
4. 检查来源是否已撤回或存在 failed/needs_review/partial 回执。
5. 依赖 OneBot 私有 API 或硬编码 QQ 平台的业务插件，需要业务插件适配。

链接解析器在微信群里仅 @ 时触发，可先检查该插件的 `require_at_in_group`（群组消息必须 @ 机器人），关闭后再直接发送链接测试。这是业务插件的触发条件，适配器不会伪造 @ 或强制唤醒全部群消息。视频发送、服务端回执和暂存清理见[视频说明](video-quality.md)。

微信管理左侧列出各账号及登录状态，右侧依次完成扫码和 AstrBot 接入；页面顶部显示内置引擎状态。旧的“连接测试”页面及其接口已移除。页面显示在线不能证明模型或业务插件已配置成功。

## 图片与媒体

收到视频直接忽略；发出视频取消 50 MiB 来源和约 25 MiB 播放副本策略限制，兼容 MP4 保留源文件，其他来源仅按源尺寸和帧率转换编码。实际边界见[视频说明](video-quality.md)。请用新发送的视频验收；旧视频不会被更新。

图片仍为图片消息。内置引擎保留完整 JPEG 原字节；PNG 等转为完整尺寸高质量 JPEG。预览仍会压缩，应点“查看原图”。若新图片依旧只有小尺寸，确认日志出现 `integrated-20261110-media-lifecycle`，账号由集成版 UI 登录，机器人配置中没有旧外部 `server_url`，且业务插件输出的源图足够清晰。旧消息不会因更新而变清晰。

图片最多 10 MiB，语音源最多 26,214,383 字节、总长 300 秒。视频和语音准备需要 FFmpeg/FFprobe，官方 AstrBot 镜像已带相关程序。HTTP(S) 支持合法的自定义端口；已配置的 AstrBot 渲染服务支持内网地址，其他 URL 保留公网及逐跳重定向校验。

王者数据查询等插件通过 `html_render(return_url=True)` 得到的图片可直接发送。首条回复尚未提交时，URL 或媒体校验失败不锁定来源，业务插件可发送文本降级。已部分发送、取消或回执不确定仍保留人工核查保护。

聊天记录解析深度在机器人绑定配置的 `provider_settings.quoted_message_parser` 中设置。接收记录内的媒体目前显示类型占位符。输出通过标准 Node/Nodes 生成聊天记录卡片，支持文本、图片和嵌套；节点内的语音、视频按顺序独立发送，文件暂不支持。真实微信上的卡片显示与内嵌图片可用性仍需用账号验收。

视频 job 最多等待一小时；不兼容的编解码器仍可能被 Native 拒绝。用户发送的视频及其缩略图不自动下载，不交给 AstrBot。PDF 已移除，普通文件暂不支持。

## 内存预算

1.1.2 内置引擎在 Ubuntu 24.04、未登录的独立测试账号上测得以下进程常驻内存（RSS）：

| 场景 | Native 内存 |
| --- | --- |
| 空闲，无账号 / 一个未登录账号 | 约 17 / 18 MiB |
| 暂存 50 MiB 来源时的峰值 | 约 120 MiB |
| 暂存 100 MiB 来源时的峰值 | 约 221 MiB |
| 暂存结束后 | 约 20 MiB |

[测量记录](https://github.com/qsc20001102/astrbot_plugin_webridge/actions/runs/42838163884)只覆盖本版引擎和本地暂存，不包含 AstrBot 的 Python 进程、业务插件、微信登录后的同步缓存、实际发送或 FFmpeg 转码。暂存落盘不代表整个发送链路都使用流式内存，来源仍会读入内存。

容量规划可先为本插件与 Native 额外预留 **200–300 MiB 常驻空间**；这是部署预算估算，已登录账号尚未实测。处理百兆视频时还应额外预留 **0.5–1 GiB 或更多**，并发、分辨率和转码会继续增加占用。AstrBot 自身、其他业务插件及本地模型另算。

## 回执与数据

微信消息适配器状态库保存游标、消息身份、撤回和发送回执，不保存 Token 或日常消息正文。Native 自身会保存其工作所需的账号、聊天与媒体数据，属于独立登录目录；卸载前备份整个 `data/plugin_data/astrbot_plugin_webridge`。

`accepted` 表示服务已接受请求。超时、断线或部分成功时查询原幂等键/job，不自动换键重发。先核查微信实际显示，再决定是否手动发送一条新消息。

退出登录保留文件，重启保留账号和游标。卸载会停止微信消息适配器消息平台和引擎；其他消息平台不受影响。不要通过删除状态库来处理发送超时，这会丢失去重与回执信息。
