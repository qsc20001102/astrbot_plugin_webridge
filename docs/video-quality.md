# 视频消息

接收和发送采用不同处理方式：

| 方向 | 处理 |
| --- | --- |
| 用户发送视频给机器人（私聊、群聊） | 直接忽略；Native 不自动下载视频和缩略图，适配器不创建 AstrBot 事件，不调用模型或业务插件 |
| 用户引用视频并附带文字 | 只交付文字与引用信息，不查找或下载被引用视频 |
| 机器人发送兼容 MP4 | 源视频完整字节作为播放副本，画面、音频、帧率与 SHA-256 保留 |
| 机器人发送其他受支持的电影容器/编码 | 必要时转换为 H.264/AAC，保持来源尺寸与帧率，不按体积降低画质 |

已移除旧的 **50 MiB 来源、26,214,383 字节播放副本、1080p、60 帧、1 小时时长**策略限制。兼容转换采用 CRF 18，不设目标大小、最高码率或 `-fs` 截断。编码需要偶数尺寸时最多补齐一行/列。仍以视频消息发送，不改为文件，不自动切段或重发。

字节保留条件为 MOV 家族中的 MP4、H.264/yuv420p、Baseline/Main/High 系列、方形像素且无旋转变换，可选单声道/双声道 AAC-LC 44.1/48 kHz。其他来源仍可能需要兼容转换，不能承诺所有编码都能原样播放。完整帧、时长、容器、摘要、账号授权与撤回检查保留。

## 真实边界

“取消插件大小限制”不能改变微信和部署环境的能力。现有 Native 传输描述符使用 32 位长度，加密填充后仍需可表示，来源最多能表示 4,294,967,279 字节；这**不代表已经验证可发送近 4 GiB 的视频**。引擎仍使用内存缓冲，实际可用内存、磁盘、网络、微信服务端和客户端解码能力都可能更早失败。

外部 URL 保留公网校验、重定向校验和读取超时。准备进程仍有超时和资源保护，发送 job 最多等候一小时；超时后保留原任务和回执状态，不自动重发。服务器拒绝或资源不足会如实报错，不再通过压小视频规避错误。

## 安装与验证

安装完整更新包并重启 AstrBot，启动日志应出现 `integrated-20261110-media-lifecycle`。清单的 `video_size_policy: protocol_only`、`incoming_video_download: false`、`temporary_media_sources: true` 和引擎 SHA-256 一起核对，避免调用旧二进制。已有账号和消息平台可继续使用，旧消息不会被更新。

回执有画质元数据时，日志显示 `source_preserved=True/False` 和源/播放字节数。手工配置的外部 Native 仍遵循外部服务自身的能力。

## 本地文件与解析插件

视频通过现有 `/uploads?temporary=true` 上传到内置引擎。源文件和需要的转码、缩略图暂存以加密文件存放在账号 `agent/temporary-media`，SQLite 只保存来源身份和任务记录。兼容视频直接复用源暂存；成功写入微信账号媒体缓存后，不再把完整视频另存为 SQLite 媒体副本。原始文件仍归调用插件所有，本适配器不会删除它。

后台每 60 秒检查一次：任务获服务端受理且消息与媒体写入均完成后，至少保留 60 秒再删除发送暂存；未提交的孤立上传保留一小时。共享源仍被其他任务使用、结果不确定、可重试或需要修复账号缓存时继续保留。重启后继续检查。已有持久上传和微信正常媒体缓存不会被清空。

解析插件可能先发预览卡片，再单独发视频。“已回复”可能只对应前一条消息。现在每次成功的视频发送会记录 job、服务端消息 ID 和源字节数；这些回执表示服务端受理，手机端接收和播放仍需实际确认。解析插件把视频装入 `Node/Nodes` 时，适配器按节点顺序拆成独立视频，支持的文字、图片继续保留卡片署名和时间。

完全没有回复时，可按日志中的“收到发送请求”“视频任务已创建”“视频已获服务端回执”判断进度。没有第一条说明尚未调用适配器发送；链接解析器可检查下载失败提示（`show_download_fail_tip`）、媒体大小/时长限制和防抖。部分解析器在下载失败且关闭提示时会返回空结果。媒体读取或格式校验失败会记录“媒体准备失败，未提交发送”，不会记录为视频发送成功。

离线测试覆盖私聊/群聊接收忽略、视频引用不下载、超过 50 MiB 的完整源上传、原生分块与完整性核对，以及真实 FFmpeg 的大 MP4 字节保留、4K 与 120 帧来源保留和 4K 兼容转换。未使用真实微信账号发送；收件端接收、播放与超大视频服务端接受范围仍需实际验收。
