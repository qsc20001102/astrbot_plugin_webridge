# 视频消息

接收和发送采用不同处理方式：

| 方向 | 处理 |
| --- | --- |
| 用户发送视频给机器人（私聊、群聊） | 直接忽略；Native 不自动下载视频和缩略图，适配器不创建 AstrBot 事件，不调用模型或业务插件 |
| 用户引用视频并附带文字 | 只交付文字与引用信息，不查找或下载被引用视频 |
| 机器人发送兼容 MP4 | 源视频完整字节作为播放副本，画面、音频、帧率与 SHA-256 保留 |
| 机器人发送其他受支持的电影容器/编码 | 必要时转换为 H.264/AAC，保持来源尺寸与帧率，不按体积降低画质 |

已移除旧的 **50 MiB 来源、26,214,383 字节播放副本、1080p、60 帧、1 小时时长**策略限制。兼容转换采用 CRF 18，不设目标大小、最高码率或 `-fs` 截断。编码需要偶数尺寸时最多补齐一行/列。仍以视频消息发送，不改为文件，不自动切段或重发。

字节保留条件为 MOV 家族中的 MP4、H.264/yuv420p、Baseline/Main/High 系列、方形像素且无旋转变换，可选单声道/双声道 AAC-LC 44.1/48 kHz。其他来源仍可能需要兼容转换，不能承诺所有编码都能原样播放。完整帧、时长、容器、摘要、账号授权与撤回检查保留。

## 真实边界

“取消插件大小限制”不能改变微信和部署环境的能力。现有 Native 传输描述符使用 32 位长度，加密填充后仍需可表示，来源最多能表示 4,294,967,279 字节；这**不代表已经验证可发送近 4 GiB 的视频**。引擎目前仍使用内存缓冲和 SQLite 暂存，实际可用内存、磁盘、SQLite 单值上限、网络、微信服务端和客户端解码能力都可能更早失败。

外部 URL 保留公网校验、重定向校验和读取超时。准备进程仍有超时和资源保护，发送 job 最多等候一小时；超时后保留原任务和回执状态，不自动重发。服务器拒绝或资源不足会如实报错，不再通过压小视频规避错误。

## 安装与验证

安装完整更新包并重启 AstrBot，启动日志应出现 `integrated-20261108-video-policy`。清单的 `video_size_policy: protocol_only`、`incoming_video_download: false` 和引擎 SHA-256 一起核对，避免调用旧二进制。已有账号和消息平台可继续使用，旧消息不会被更新。

回执有画质元数据时，日志显示 `source_preserved=True/False` 和源/播放字节数。手工配置的外部 Native 仍遵循外部服务自身的能力。

离线测试覆盖私聊/群聊接收忽略、视频引用不下载、超过 50 MiB 的完整源上传、原生分块与完整性核对，以及真实 FFmpeg 的大 MP4 字节保留、4K 与 120 帧来源保留和 4K 兼容转换。未使用真实微信账号发送；收件端接收、播放与超大视频服务端接受范围仍需实际验收。
